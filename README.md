# pap-main

Flask-приложение с регистрацией и входом через MySQL.

## Запуск

Нужны Python 3.14+, uv и доступ к MySQL. Создайте базу и пользователя MySQL,
затем задайте переменные окружения (реальные секреты не добавляйте в Git):

```bash
uv sync
export DB_HOST=localhost
export DB_PORT=3306
export DB_NAME=pap_main
export DB_USER=pap_main
export DB_PASSWORD='укажите_свой_пароль_БД'
export SECRET_KEY="$(uv run python -c 'import secrets; print(secrets.token_hex(32))')"

mysql -h "$DB_HOST" -P "$DB_PORT" -u "$DB_USER" -p "$DB_NAME" < schema.sql
uv run python src/app.py
```

Страница регистрации: `http://localhost:5000/`, вход: `/login`.
`PORT` позволяет изменить порт сервера. Приложение использует MySQL;
имеющийся в репозитории `users.db` в этих обработчиках не используется.

Для существующей таблицы проверьте наличие колонок из `schema.sql`, в частности
`password_hash VARCHAR(255)`: `CREATE TABLE IF NOT EXISTS` не обновляет её структуру.

`SECRET_KEY` должен быть постоянным и одинаковым для всех процессов приложения.
Если переменная не задана, генерируется временный ключ, и после перезапуска
сессии станут недействительными. Ранее опубликованные в исходниках пароль БД
и ключ сессии следует заменить. В production используйте HTTPS, защищённые
cookie (переменная `SESSION_COOKIE_SECURE=1`) и production WSGI-сервер вместо `app.run`.

## Хранение и проверка паролей

- `POST /user_register` принимает JSON с `name`, `email`, `password` и
  необязательным `phone`. Пароль длиной 8–1024 символа хэшируется **на сервере**
  через Werkzeug: PBKDF2-SHA256, 1 000 000 итераций, случайная соль длиной 16.
- В MySQL сохраняется только `password_hash`. Соль и параметры алгоритма уже
  включены в строку хэша. SQL-запросы используют связанные параметры.
- `POST /user_login` принимает JSON с `email` и `password` и проверяет его через
  `check_password_hash`. При успехе в сессию записывается только ID пользователя.
- Пароли и хэши не возвращаются клиенту; демо-пароли и проверка учётных данных
  в браузере удалены. Пароль передаётся серверу только по HTTPS в production.
- Старые открытые пароли не принимаются вместо хэшей. Для таких записей нужна
  отдельная миграция либо сброс пароля; автоматической миграции здесь нет.

## Проверки

```bash
uv run python -m unittest discover -s tests -v
```

Тесты используют Flask test client и подменяют подключение MySQL, поэтому
рабочая БД не нужна и не изменяется. Проверяются сохранение хэша, случайная соль,
точное сохранение пробелов в пароле, успешный и неуспешный вход, валидация,
обработка ошибок БД и отсутствие паролей/хэшей в ответах и сессии.
